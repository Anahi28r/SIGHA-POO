# Tu primer repositorio de SIGHA

Esta carpeta ya contiene los archivos y textos que puedes subir. No necesitas inventar el contenido ni terminar toda la aplicación antes de crear el repositorio.

## 1. Extraer el paquete

Extrae `SIGHA-POO_repositorio.zip`. Abre la carpeta SIGHA-POO y comprueba que dentro estén README.md, practicas, aplicaciones, sigha, docs y prototipo-web.

No subas solo el ZIP: GitHub debe mostrar los archivos y carpetas para que se puedan revisar.

## 2. Entrar a GitHub

Abre [GitHub](https://github.com/) e inicia sesión. Si no tienes cuenta, completa tú el registro y la verificación que te soliciten.

## 3. Crear el repositorio

En el menú de creación elige **New repository**. Puedes usar estos datos:

- **Repository name:** `SIGHA-POO`
- **Description:** `Prácticas de Programación Orientada a Objetos en Python y su aplicación al Sistema de Gestión de Horarios Académicos SIGHA.`
- **Visibility:** si el profesor no ha indicado otra cosa, puedes empezar con Private. Para que pueda verlo, necesitará acceso como colaborador. Si exige un enlace público, confirma ese requisito y revisa con el grupo los documentos y datos que se publicarán.
- No agregues un README adicional: el paquete ya incluye el suyo.

Selecciona **Create repository**. Elige tu propia cuenta como propietaria, salvo que el grupo tenga una organización acordada.

## 4. Subir los archivos

En el repositorio recién creado, usa el enlace **uploading an existing file**. En un repositorio con archivos también puedes encontrar **Add file → Upload files**.

Arrastra el contenido de SIGHA-POO a la zona de carga: README.md y las carpetas. El README debe quedar en la raíz del repositorio, no dentro de otra carpeta SIGHA-POO adicional. Incluye también los archivos `.gitignore` y `requirements-originales.txt`; si no ves el primero, activa temporalmente la visualización de archivos ocultos en el explorador.

Mensaje sugerido para esta primera carga:

```text
Organiza prácticas de POO y agrega integración inicial de SIGHA
```

Confirma la carga con el botón que muestre GitHub para guardar los cambios. Si tu cuenta tiene reglas que exijan una rama y una solicitud de cambios, sigue ese flujo.

## 5. Comprobar la entrega

En la página principal deben verse el README y las carpetas. Abre una práctica original, su aplicación y la explicación de relación con SIGHA. Comprueba también que el informe y el UML se pueden descargar.

Copia el enlace completo de tu repositorio para entregar, con una forma similar a `https://github.com/tu-cuenta/SIGHA-POO`. La página inicial `https://github.com/` por sí sola no identifica tu trabajo.

## 6. Continuar durante el curso

Cada vez que incorpores una práctica, sube el archivo, añade su explicación y actualiza la bitácora con la fecha real. Utiliza un mensaje que describa lo que cambió, por ejemplo `Aplica encapsulamiento a la capacidad del aula`.

La primera carga registra que reúnes el material ahora. No hace falta simular que cada práctica se publicó en una fecha pasada.

## Qué mostrar al profesor

1. README: qué es SIGHA y cómo se organiza el repositorio.
2. Práctica original: evidencia de lo trabajado en clase.
3. Relación de prácticas: qué idea se aprovecha y por qué.
4. Aplicación Python: dónde se demuestra esa idea en SIGHA.
5. Informe y UML: definición y diseño del proyecto.
6. Bitácora: aportes reales y siguientes pasos.

La interfaz web es una demostración complementaria e independiente. El trabajo de POO en Python está en las carpetas sigha y aplicaciones.

## Participación de los cinco integrantes

Una persona crea el repositorio y los otros cuatro necesitan acceso para subir sus aportes desde sus propias cuentas.

1. La persona propietaria abre el repositorio y entra en **Settings**.
2. En la sección de acceso, entra en **Collaborators** y pulsa **Add people**.
3. Busca la cuenta de cada compañero y envía la invitación. Repite para los cuatro.
4. Cada compañero acepta su invitación y entra con su propia cuenta.
5. Acuerdan qué ficha de la carpeta aportes revisará y adaptará cada uno.
6. Cada integrante sube o edita su ficha y su código, si corresponde, con un mensaje que describa su aporte real.
7. Actualizan la bitácora y enlazan la evidencia de esa contribución.

La carpeta inicial contiene propuestas sin autor asignado. No conviene entregar las cinco como si los cinco integrantes ya las hubieran redactado, revisado y subido.

[Instrucciones oficiales para invitar colaboradores](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository).
